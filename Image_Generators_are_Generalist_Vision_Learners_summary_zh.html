文章摘要

这篇论文提出一个强命题：图像生成器不仅能生成视觉内容，也可能已经通过生成式预训练学到了通用视觉理解能力。作者把这种能力与大语言模型的生成式预训练作类比，认为图像和视频生成模型的零样本视觉理解行为类似 LLM 在语言理解和推理中的涌现能力。论文要回答的不是“生成器能否偶尔画出分割图或深度图”，而是：一个强图像生成器在轻量指令微调后，能否在现代视觉理解基准上接近或超过专门模型，同时不牺牲原始图像生成能力。摘要明确写道，本文证明 “image generation training serves a role similar to LLM pretraining”，并提出 Vision Banana：在 Nano Banana Pro 基础上，用少量视觉任务数据和原始生成训练数据混合进行指令微调得到的通用视觉模型。

方法的关键是把视觉感知任务统一参数化为 RGB 图像生成。语义分割、实例分割、指代表达分割、度量深度和表面法线都被写成“按提示生成可解码可视化图”的任务。例如分割输出是按提示颜色编码的 mask；深度输出是可逆的 false-color depth map；法线天然可以映射到 RGB 通道。这样，模型不用额外添加专门解码头或任务损失，而是继续使用图像生成作为统一接口。作者强调这一格式桥接可以让输出被解码回标准视觉任务结果，从而在常规 benchmark 上量化评估。

实验覆盖 2D 语义理解、3D 单目结构理解和原有生成能力。Table 1 显示，Vision Banana 在 RefCOCOg UMD val 上 cIoU 为 0.738，略高于 SAM3 Agent 的 0.734；ReasonSeg gIoU 为 0.793，高于 SAM3 Agent 的 0.770；Cityscapes mIoU 为 0.699，高于 SAM3 的 0.652；SA-Co/Gold 实例分割 0.540，略低于 DINO-X 的 0.552，但仍接近。在 3D 上，四数据集平均深度 δ1 为 0.929，高于 Depth Anything 3 的 0.918；表面法线平均角误差 18.928，低于 Lotus-2 的 19.642。生成能力方面，Vision Banana 相对 Nano Banana Pro 在 GenAI-Bench 文生图中 53.5% 胜率，在 ImgEdit 编辑中 47.8% 胜率，说明微调后基本保持原生成能力。

论文的论证重点在于范式转移：视觉理解不必总是由判别式表征、专门架构、专用损失和任务头来承担；图像生成本身可以成为类似文本生成的通用输出接口。作者认为，Vision Banana 的结果说明 Nano Banana Pro 已经拥有可被指令调出的视觉理解表征，“only needed to be unlocked with instruction tuning”。同时，论文也承认未来仍有明显问题：当前评估主要是单目图像；多视角、视频、与 LLM 的协同推理仍待探索；生成式视觉框架的计算开销显著高于轻量专门模型，因此部署前还需要加速和降本。

1. 提出问题

论文提出的核心问题是：图像生成模型是否只是会“画图”，还是已经在生成式预训练中学到了可迁移到视觉理解任务的通用表征？引言中作者说，他们要研究视觉生成模型是否是 “secretly generalist vision learners”，也就是训练于图像/视频生成的模型是否发展出适用于分割、深度、法线等理解任务的内部表征。

这个问题背后有两组张力。第一，先进生成器已经能生成高保真、语义可控的复杂视觉内容，但主流视觉表征学习仍主要依赖监督判别学习、对比学习、自举学习和自编码等非生成路线。第二，已有生成器用于视觉理解的工作能产生类似输出可视化的图像，却往往不能严格按提示生成可解码格式，因此难以在现代 benchmark 上给出强量化结果；另一些方法通过专门模块和全量微调取得单任务 SOTA，但 “sacrifice the model’s generality across other understanding and generation tasks”。

2. 分析问题

作者把问题拆解为“能力是否存在”和“如何测量”两个层面。能力层面，如果一个预训练图像生成器只需少量视觉任务指令微调，就能在多类视觉理解任务中达到或接近 SOTA，并且保持原来的图像生成能力，那么就有理由认为它已经具备视觉理解基础模型的内部表征。引言中给出的判据是：若微调模型在 benchmark 上表现 “at or near SOTA”，同时保留生成能力，就构成强证据。

测量层面，生成器输出的是 RGB 图像，而视觉任务的标准指标需要 mask、depth、normal 等结构化结果。因此论文把视觉任务输出全部重写为可逆或可解析的 RGB 可视化。分割任务通过颜色映射把类或实例编码为 RGB mask；深度任务通过幂变换和 RGB 立方体边缘插值建立度量深度到 RGB 的双射；法线任务直接使用相机空间方向到 RGB 的映射。这样，图像生成器只需按提示生成图像，评估端再把图像解码回标准任务输出。

这种分析把“视觉理解”从模型结构问题转化为接口问题。作者认为，类似 LLM 通过文本生成统一语言理解与推理，图像生成也可以成为视觉任务的统一接口。Discussion 中写道，图像生成可以作为 “the universal interface for computer vision”，这意味着模型权重在任务间共享，只有 prompt 和解码规则变化。

3. 解决问题

解决方案是 Vision Banana。作者以 Nano Banana Pro 为 base model，在原始生成训练混合中加入很低比例的视觉任务数据进行轻量指令微调。视觉任务数据包括来自网页图像的内部模型标注，以及渲染引擎生成的 3D 合成数据；论文特别声明 “no training data from our evaluation benchmarks is included”，以支持零样本迁移评估的可信度。训练目标不是把模型改造成专门分割器或深度估计器，而是教它按自然语言指令生成可解析 RGB 输出。

2D 任务中，语义分割要求模型按 prompt 中指定颜色为每类像素着色，类名可以是任意文本；实例分割采取 per-class inference，由模型为同类不同实例动态分配颜色；指代表达分割则用自由文本指定要分割的对象，测试模型对外观、动作、异常用途和多语言文本的理解。3D 任务中，度量深度通过严格可逆的 RGB false-color 映射解码回米制深度；表面法线用方向向量到 RGB 的自然对应输出。作者用 Table 1 到 Table 4 证明这种生成式接口可在多个任务上与专门模型竞争。

结果显示，该方法最强的论证点不是某一个任务的绝对领先，而是单一生成模型在多个 2D、3D 和生成任务上同时成立。Table 1 的概括是，Vision Banana “surpasses or rivals SOTA specialists across visual generation and understanding”。同时，论文在实例分割上也保持谨慎：SA-Co/Gold 中 Vision Banana 仍低于 SAM 3 和 DINO-X，作者明确说 “still lags behind in instance segmentation”，说明统一生成接口并未消除所有专门任务难点。

4. 赞成什么

论文赞成生成式视觉预训练作为基础视觉模型的中心路线。它把图像生成器类比为 LLM 的 base model：预训练负责学习世界结构和通用表征，指令微调负责让模型按任务格式输出。Discussion 中作者明确说，大规模图像生成预训练自然获得 robust visual understanding capabilities，并认为这可能推动计算机视觉的范式转移。

论文也赞成“图像生成即通用接口”的观点。通过把分割、深度、法线等结果都表示成 RGB 图像，模型可以用同一个生成通道完成多种任务。这一设计支持跨任务共享权重、自然语言提示控制和统一解码评估。作者还赞成生成模型对多解视觉任务的适配性：因为生成模型学习输出分布，它们可以比单一均值回归式判别模型更自然地处理歧义，减少对专门架构和定制损失的依赖。

5. 反对什么

论文反对把视觉基础模型主要限定在判别式表征学习、对比学习或自编码路线中。引言指出，虽然生成模型的视觉创造能力暗示其理解能力，但领先视觉表征方法通常并不属于生成建模家族；本文则试图证明生成预训练本身可以成为通用视觉学习器。

论文也反对为每个视觉任务构造专门模块、专门损失和全量微调的路线。作者承认这些方法能利用生成器预训练特征并取得单任务结果，但批评它们会牺牲跨理解与生成任务的一般性。相反，Vision Banana 只做轻量指令微调，并保持 Nano Banana Pro 的生成能力。

论文的限制主要在 Future Work 中体现。当前评估集中在单目图像输入，多视角和视频尚未展开；与大语言模型结合以增强跨模态推理仍是下一步；更重要的是，使用 Nano Banana Pro 这类图像生成器 “incurs a significantly higher computational overhead than running lightweight specialist models”。因此，尽管论文主张生成器可能成为通用视觉学习器，实际部署仍需要解决成本、速度和扩展任务多样性的问题。
